# DYEFIELD — FFA random safe spawns (S1–S7)

Owner (2026-09-29, while playing FFA): "in FFA it is better to have random spawn points, not the same ones over and
over."

Today each FFA runner owns one drop pad for the whole match (`world.ts respawnRunner → this.slots[r.id]`, with a
seeded shuffle only at the match start). This contract replaces that. It changes CONTRACT_FFA F1/F6/F7 in FFA only.

**Non-negotiables**
- TEAMS (turf, and washout per CONTRACT_WASHOUT) keeps its team bases and spawns, and every TEAMS determinism hash
  stays identical.
- The FFA hashes change: this is a deliberate FFA behaviour change. Record the new ones.

  sites.
- A site is `{pos, yaw}`, and the yaw faces toward the map's open centre.
- `CHANGED(SPAWNS core, 2026-09-30)` as built:
  - Size (`--count auto`): one site per 200 m² of core floor, even (rot180 mirror pairs), clamped to 16–24. Measured
    core floor: pier18 4936, lockwell 4368, cinder 5144 m² → **24 / 22 / 24** sites.
  - Which new sites: a first build added them by plain farthest-point (spread only). On pier18 that pool left the

## S2 Spawn choice (core, deterministic: the match RNG stream only)

**Match start:** the 8 runners take 8 sites chosen for spread. That is a seeded farthest-point pick over the pool,
starting from a seeded random site.

**Respawn:** after the usual 3 s, a washed runner takes a site chosen like this:
1. **Candidates:** every site with no runner within 3.0 m, excluding the runner's last 2 sites.
2. **Score each candidate:**
   - `dmin` = distance to the nearest living foe (in FFA every other runner is a foe).
   - `seen` = true if any living foe within 30 m has line of sight to the site at chest height. Use the same ray
     as `canSee`; mist `hideRange` applies.
   - `nearKiller` = distance to the runner who washed you, if they are alive.
3. **Safe set:** candidates with `!seen && dmin ≥ 12 && nearKiller ≥ 15`. If fewer than 3 are safe, take the 3 best
   by `dmin` (with seen ones last).
4. **Pick** uniformly at random, using the seeded RNG, from the safe set.

**Output:** the choice is exposed on the runner as `spawnSite` (the index), and a `{t: 'spawn', pid, site, x, y, z,
yaw}` event is pushed. The HUD, the view and the harness read these.

`CHANGED(SPAWNS core, 2026-09-30)` as built (`core/match/world.ts` `ffaStartSites` / `chooseSite`, numbers in
`MATCH_FFA`):
- The fallback of step 3 in its strict form: while any candidate is unseen, the set is the (up to) 3 unseen ones with
  the largest `dmin`; a seen site is drawn only when no candidate is unseen. The literal "3 best by dmin, seen ones last"
  topped a 1–2 site unseen set up with seen sites and put 43–50 % of pier18 respawns in view.
- Distances are 3-D; `dmin` and "no runner within 3.0 m" use living runners; `seen` runs the `canSee` ray from each
  living foe's eye to the site chest (`HITBOX.height / 2`), and beyond the map's mist `hideRange` nothing sees.
  - `CHANGED(SPAWNS skeptic fix, 2026-09-30)`: the chest is `site.y + MOVE.skin + HITBOX.height / 2` (where `canSee`
    aims at the respawned runner: `Runner.respawn` puts its feet `MOVE.skin` over the site), and **the mist rule is
    gone**: `canSee`'s mist hides only SLICK targets, and a freshly respawned runner is tall, so a foe 25–30 m away in
    Cinder's mist does see it. The same test is in `world.ts siteSeen`, `_harness/spawn_audit.ts` and the
    `gen_ffa_spawns.ts` model. Before: on cinder 15–31 % of bot-match respawns landed inside a live foe's `canSee`
    ≤ 30 m while the audit counted them unseen. After (core3 `bots_see.mts`: every live foe's `canSee` ≤ 30 m right after
    the respawn tick, the same matches as `probe_bots --mode ffa`): see the S6 note.
- The killer is the credited washer, else (a TURF sea wash) the last foe hit inside the 5 s sea-credit window.
- All draws come from one FFA spawn stream (seeded from the match seed; exactly one draw per respawn). An FFA respawn
  resolves after every living runner has moved that tick, in runner-id order, so the choice sees this tick's positions
  and the runners respawned just before it.
- `spawn` events: one per runner at construction (the match-start sites), then one per respawn, right after its
  `respawn` event. `yaw` is in radians (as every world yaw). `MatchWorld.spawnSites` is the pool (yaw radians),
  `spawnSiteOf(r)` the runner's current site, `spawnFor(r)` its latest spawn point.
- If no site passes "no runner within 3 m" after allowing the last 2 sites, the site farthest from every runner is
  used (never seen with 8 runners on these pools).

## S3 No permanent FFA pads; a transient drop-in marker

- In FFA there are no owned pads:
  - remove `crewPads` ownership, the own-pad slick/refill rule and the others-pushed-out rule;
  - remove the FFA pad-floor lock, since no permanent disc sits on the floor any more.
- In place of pads, a drop-in marker plays at the chosen site for the drop plus the protection window (about 2.5 s).
  - It is a crew-coloured glowing ring and the crew's mark, conformed to the ground. Reuse the conforming pad
    generator from `view/mapview.ts` (`addFfaPads` geometry / its soup-gather + spoke walk).
  - It is translucent in the centre, so floor paint stays visible, and it fades out.
  - It is visible to everyone: a fair warning.
- **TEAMS:** the A/B team pads are unchanged.
- **FFA scenery:** the A/B team pads stay as neutral scenery (their F1 behaviour).
- `CHANGED(SPAWNS core, 2026-09-30)`: core part done. FFA runners get no own / enemy pad (`MatchWorld.padOf(r)` →
  `null` in FFA), the `otherPads` push-out is gone from `Runner`, and no mode locks floor (`lockDiscs([])` clears an old
  lock on a reused painter). **Compatibility field for the UI stage:** `MatchWorld.crewPads` still exists, is always
  `[]` and is marked `@deprecated`, so today's `main.ts addFfaPads(...)` and `testsurface` compile and draw no pads.
  The UI stage switches the view to `spawnSites` / `Runner.spawnSite` / the `spawn` event and then deletes the field.

## S4 Spawn protection in FFA, both rules

- 2.0 s after any spawn, or until the runner fires, subs or uses a special: no damage, cannot be washed. This is the
  same `Runner.protectedT` as CONTRACT_WASHOUT W1.
  - CHANGED(SPAWNS): W1's "WASHOUT only" becomes "WASHOUT, and FFA in either rule".
  - TEAMS TURF stays without it, so its hashes are unchanged.
- **Bots** (`director.ts`): never target a protected runner, never path to a site to camp it, and drop the old
  own-pad logic in FFA. Spawn grace (director.ts ~909) is kept or folded into protection.
- `CHANGED(SPAWNS core, 2026-09-30)` as built: protection is granted on every FFA **respawn** (not at the match start,
  as W1), for `washout.spawnProtectSeconds` (2.0 s), with the W1 end rules. The spawn grace (a runner < 4 s from its
  respawn is no target unless it hit the bot) is kept on top. The bots have no goal that is a site; an FFA refill uses
  own dye only (the nearest own-dye spot within 18 m, else the nearest zone holding own dye, else painting on for 3 s).
