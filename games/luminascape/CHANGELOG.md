## Architecture
- **Terrain**: chunked heightfield (`chunks` Map keyed cx,cz; each = Float32 `heights[65*65]` source-of-truth + displaced PlaneGeometry 64×64 cells + per-chunk RGBA `splat` DataTexture). `getHeight` bilinear. `makeGroundMat` = MeshStandardMaterial + `onBeforeCompile` world-tiled splat blend (R grass/G dirt/B rock/A sand) + auto-rock on slope. Per-chunk `crk` RedFormat crack texture (`uCrack` Worley overlay) and `tnt` RG paint-tint texture (`uTint`, 12-type overlay). Submerged tint + per-channel climate tint (`uChanTint`/`uChanMix`) preserved.
- **Rivers**: hand-written flow-map water material (Valve ping-pong), draped ribbon, carve channel + auto-beach. Oceans: vendored `Water.js` at `seaLevel`; auto-beach at the waterline.
- **Placement**: `PLACEABLES` catalog (Trees/Foliage/Rocks/Buildings/Fences/Crops/Animals). Props in `MODELS` (loaded upfront); Buildings lazy via `ensureBuilding`; Animals lazy rigs via `ensureAnimal` from `assets/models/animated/<key>.glb`. `placedObjects[]`, `animals[]`, `collidables[]`.
- **Assets**: props/trees/foliage/rocks/fences from Kenney-style nature kit (`assets/models/*.glb`); buildings `assets/models/buildings/*.glb` (46, CC-BY, CREDITS.txt); animals `assets/models/animated/*.glb` (79 rigged CC0 Quaternius) + `assets/models/wildlife/*.glb` (37 static). Terrain PBR + water maps copied under `assets/`.
- **`_MAT_FIX` / `_fixMat(o)`**: this GLB pack ships a systematic color-wash (saturated colors lightened+blue-shifted: `leafsGreen`→teal #70e6d6, `grass`→teal, `stone`→pale-blue #ddf2f5, `colorRed`→pink). `_fixMat` remaps known material names to a natural palette at load (called in both `loadModels` + `ensureBuilding`). Source mats are shared by clones, so fixing once fixes all instances. (House roofs = unnamed #eaffff mint, left as a cozy pastel.)

## Feature history

### 2026-07-02 (16) — b17: quality tiers now control MSAA + shadow cadence (real graphics settings)
**Owner ask:** wire the shadow-throttle + MSAA-drop fixes into the existing High/Med/Low quality setting instead of hardcoding them — so the quality control (which previously *only* changed grass density, and thus couldn't dent a fill-bound frame) becomes a real graphics tier that both the user (⚙ toggle) and the auto-governor can use.
**setQuality(q) now sets, per tier:**
- **High** — grass 14000, **MSAA 4**, shadows re-render **every frame** while panning, **1024** shadow map. Identical to before → zero FPS compromise on a strong GPU.
- **Med** — grass 8500, **MSAA 2**, shadows every **2nd** frame while panning, 1024 map.
- **Low** — grass 4500, MSAA 2, shadows every **3rd** frame while panning, **768** map.
**Mechanism:** `_applyMSAA(n)` sets `.samples` on both composer ping-pong targets + `.dispose()` (renderer rebuilds the multisample FBO at the new count); `_applyShadowMap(size)` resizes + disposes `sun.shadow.map`. **BLINK is bounded to deliberate tier changes** (manual ⚙ or governor steps on a 6-9s cooldown) — never per-frame — because initial vars (`_msaa=4`, `_shadowMoveEvery=1`, 1024) match the constructed state, so boot + staying on High reallocate nothing.
**Shadow throttle** (`render()`): the idle animals/wind refresh stays ~8Hz; only the CAMERA-MOVED refresh is gated to every `_shadowMoveEvery`-th frame — kills the "shadows ticking, movement slow" hitch. Shadows snap correct within ~2 frames of the camera stopping (8Hz idle path catches it).
**Verified:** node --check OK; badge b17; tiers switch samples 4→2→2 and shadow 1024→1024→768 and back (probed live); **scene + shadows render fully intact at Low AND High after the reallocations** (screenshots — tree/deer shadows cast correctly, no black frame, no persistent breakage); reverting to High restores 4x/1024. NOTE: dynamic internal-resolution scaling (the heavier fill-rate hammer) intentionally NOT added — owner chose the two low-risk fixes; resolution-scaling remains the documented next tier if these aren't enough.

### 2026-07-02 (15) — b16: FIXED-TIMESTEP sim loop (fixes low-fps slow-motion + collision tunnelling)
**Was:** `loop()` ran ONE variable step per frame with `dt=Math.min(realDt,0.05)`. Below 20fps that clamp makes the whole world run in **slow-motion** (owner's "movement is SLOW" at 20fps), and a big dt lets a mover jump far enough to skip a fence in one step (tunnelling).
**Now (Fix-Your-Timestep accumulator):** split `frame()` into **sim-only `frame(dt)`** + a new **`render(rt)`** (shadow pacing, `composer.render()`, fps meter, quality governor — all display-rate concerns). `loop()` accumulates real elapsed time and runs N equal `_FIXED_DT=1/60` sub-steps, then draws once. World speed is now identical at any frame rate; collision/movement steps stay small. `_MAX_SUB=5` + backlog-shed guards against the death-spiral; a 0.25s clamp guards tab-out. All non-loop `frame()` callers (debug/verify helpers, `shot`/`snap`) were checked — they step sim then render explicitly, so the split is transparent to them.
**Verified:** node --check OK; badge b16 live on staging; rAF loop alive (fps meter updates); **sim clock advances LINEARLY with wall-clock across two independent windows (0.00402 & 0.00393 /s, ~250s day both times)** = correct real-time, no slow-mo/accel; an animal moved over wall-clock; scene renders intact (render-split didn't break drawing); no exceptions (a throw would freeze the meter or the clock — neither did).
**NOTE — not a smoothness/FPS fix on its own** (see the profile below). This fixes *sluggishness* (the slow-mo) and *tunnelling*, per owner's explicit ask; raw FPS is a separate fill-rate problem.

**Frame-cost profile (why web sits at 20fps while preview shows 50):** the headless CDP/ANGLE context can't microbenchmark GPU time reliably (one-time reallocation/recompile spikes dominate; its own fps meter pegs ~25 regardless) — so this is diagnosed from architecture + the owner's real 50-vs-20 datapoint, which is conclusive: **cost scales with window pixel count → the game is FILL-RATE bound.** The shadow map (fixed 1024) and sim cost don't scale with window size, so they don't explain preview-vs-web; **per-pixel work does** — the full-res post chain every frame (MSAA-4 resolve + UnrealBloom + godray + colour-grade) plus scene/grass fill. And the adaptive-quality governor **only lowers grass density, never resolution or post**, so once grass is at Low it has nothing left to pull → it *sits* at 20. Shadows re-rendering every frame while the camera moves (1024 map) is a separate movement-only hitch ("shadows ticking"). **Recommended next (awaiting owner OK — carries the historical resize "blink" risk):** (1) add dynamic internal-resolution scaling to the governor (the real fill-bound cure), (2) throttle shadow re-render to every ~2 frames while moving and/or 1024→768, (3) optional MSAA 4→2.

### 2026-07-02 (14) — b15: ART-FORWARD facing correction (the real lion-glide fix)
**Root cause (owner caught it):** the earlier "lion glide" fix (b13) only sped up the yaw EASE — it measured the model's *code axis* (local +Z, which the engine aligns to velocity by construction, so it always read ~0° error) and never checked where the model's FACE actually points. Several rigs are modelled with the SPINE along local **X** (head toward +X or −X), so the engine (built assuming +Z-forward rigs) rotated them 90° wrong → they slid **broadside** to travel even while the yaw "matched."
**How each rig was diagnosed (deterministic + visual, both):** (1) placed all 129 species, measured local-space horizontal bbox with yaw frozen (dimX vs dimZ) to flag sideways candidates; (2) for the definitive answer, read each rig's named **head bone** world-position relative to its root — exact where present (`faceOff = −atan2(headVec.x, headVec.z)` snapped to 90°); (3) rotation-**frozen** straight-down screenshots (Object.defineProperty lock so snap()'s 3 capture-frames can't drift a moving rig); (4) **walk-verified**: placed each with an adjacent prey/threat so it actually moved, then compared its head-bone world direction to its ACTUAL velocity — delta <28° = head-leads.
**Result — `_FACE_OFF` filled (was empty):** lion/lioness/panther **−π/2** (head-bone +1.63), tiger **+π/2** (head-bone −1.62), moose **−π/2** (antlers make the bbox square — only the head-bone (+1.66) caught it), bison **−π/2** (true quadruped, frozen top-down + walk-verified head-first). Walk-verified head-leads deltas: lion −5.6°, tiger +4.8°, panther +16.9°, moose +2.3° (controls deer −8.4° / wolf −0.2° confirm the pipeline). Everything else stays 0.
**Trap avoided (why the visual pass is non-negotiable):** the thin-dz bbox heuristic first flagged **sloth** as spine-along-X and I set it −π/2 — but a SIDE view showed it's an **upright, arms-spread** rig (dy 0.96 tall, dz 0.37 thin body-depth; its X-width is arm span, exactly like the apes). Reverted sloth to **0** and re-verified (top-down: walks face-forward with arms perpendicular). apes/crab/birds/fish all get X-width from spread limbs/wings, not spine → 0.
**Also wired the herd/boid path:** `_updateBoids` set member `rotation.y = atan2(vx,vz)` raw — a herd's species can be bison/big-cats, so it now adds `_FACE_OFF[g.key]`. Verified with a 6-member lion herd (members walk head-first). `_updateFlocks` unchanged (hawk-only, offset 0). node --check OK; console clean on fresh boot.
