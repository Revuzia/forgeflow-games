## Per finding: what was wrong, what I changed, the repro and its number

### B-M1 (MAJOR): 4 bodies hid one squishy behind another
- Diagnosis (shell code read): `src/shell/mat.ts` brings squishies out ONE AT A TIME (`offsets(n)` = `matLayout(n)` relative to its first slot) and `bodies.placeExtras` moves only the apart ones: with the real soft body (it offers `collide`) an extra is built in shared space and KEEPS the spot it got when it came out. A body's final spot is therefore `matLayout(k + 1)[k]`, not a place in the final layout, and the old per-n layouts were not nested (the 4th body landed at (1.35, 1.23) directly in front of the 2nd, which was already out at (1.31, 0)). My probe (`RV.matSharedProbe`) reproduces both builds: the verifier's all-at-once build (n=4 0.93 / 0.77 / 0.57 at 1280x800, verifier 0.91 / 0.90 / 0.56) and the shell's incremental one (0.42 / 0.76 / 0.63). Picture of the shell flow before: `shots\mat_before_A\1280x800_A_n4.png` (an olive body behind a big pale bean, its eyes showing through the front jelly).
- Fix (`stage.ts`): `matLayout(n)` = the first n of one NESTED slot list. Wide frame (aspect >= 0.9): a plain row, 1.3 apart, the play body first then right, left, right, left. Tall frame: a chevron, the play body in front and the others behind it to either side, each further out (0.9, -1.3), (-0.9, -1.3), (1.8, -2.6), (-1.8, -2.6). Why not a staggered 2 x 2: depth at the camera's pitch of 0.27 rad shifts a body up the picture by only ~0.27 per unit while it is ~1 tall, so any body BEHIND another is mostly hidden; only lateral separation helps. Candidates I measured and rejected: 2-row layouts with a front body between two behind (0.38 .. 0.58 overlap), tall rows (bodies 46 .. 100 px on 390).
- Numbers (`node SCR\scripts\mat_shared.mjs A,B,C 1280x800,390x844,844x390 2,3,4,5 <tag> "" inc`; logs `mat_before_inc.log`, `mat_before_fin.log`, `after_mat.log`; worst pair overlap, then worst face band in brackets): see the status table; n = 5 after: 0.00 on the wide frames, 0.18 / 0.24 / 0.25 on the phone. The price is size: n = 4 camera scale 1.65 .. 2.0 -> 2.09 .. 2.33 on 1280x800 (bodies ~20% smaller), 2.4 .. 2.6 -> 3.3 .. 3.6 on the phone (~78 px wide on 390 px). Pictures: `shots\mat_rowA\1280x800_A_n4.png`, `1280x800_B_n5.png`.
- Contract (additive, doc only): `matLayout` is documented as nested in `src/contracts.ts`.

### B-m7: the hollow capsule (root cause found by bisect)
`SCR\scripts\cap_bisect.mjs epic 16 med` hides the children of the play body's rarity group one at a time: only the aura quad (`HaloQuad`, additive, in the OPAQUE list so the jelly refracts it) changes the capsule box luma (HEAD 61.7 with it, 100.1 without). Cause: three's AdditiveBlending also adds the source alpha (1.0) to the DESTINATION ALPHA, and three's transmission render target is half float and does not clamp, so inside the aura quad's rect the target held alpha 2; the transmissive capsule read that as "clear" (the picture shows the clear D-shaped half ending at the quad's straight right edge). Fix: `ADD_KEEP_ALPHA` (halo.ts), CustomBlending with colour One + One (identical to Additive for the alpha-1 shaders) and the destination alpha untouched, used by `HaloQuad` (aura and core halo), the core blob and the pool decal. After: 110.6 in every variant. (Looking at the verifier's own claim "low is fine, med / high hollow" again: this is exactly the transmission tiers.)

## Log of what I learned the hard way (for the next engineer)
- Scripts under the very long scratch path fail in node if the cwd is inside it; run from G with absolute paths. A `python3 -` heredoc hung my shell once (killed with `taskkill /T` on my own shell only).
- `cmd //c mklink /J` from Git Bash mangled the path and made a bad junction; use `New-Item -ItemType Junction` in PowerShell.
- Vite with `WH_FROZEN=1` caches module transforms per process: an edit during a running script is not picked up by it, but IS picked up by the next script; I held src edits while a measuring batch ran.
- I left no process running (checked with `Get-CimInstance` for vite / browser_render / chrome-headless / render_fix1).
